# 主旋律候选 v1（诊断阶段）

本分支只改 V2 已有的“主旋律合并”候选选择。它读取已经冻结的 raw recognition 音符，保留原始音符、原 MIDI 和各乐器分谱，不覆盖源文件。算法阶段没有重跑 MuScriptor 或重新训练模型；root 验收时另外运行了正式 `HighAccuracyService` 主旋律 smoke，确认 63.64 秒输入可生成 16 个 SVG 和 `ScoreMID`，这是链路验证，不是重新识别。另一个 49.63 秒的 vocal profile 参数试验没有改善，也没有接入生产。源样本基线为 `08bf188`，本说明对应的工作日期为 2026-09-12。

## 当前运行策略

`backend/jianpu_score/quantize.py` 已恢复旧的默认量化选择器。它不再承担这次 V2 主旋律实验，避免拒绝的动态规划实验影响其它人声或 V1 路径。

V2 的 `_select_main_melody_notes` 以原有规则作为基线：按 `round(start_sec, 5)` 分组，每个起音保留最高音。当前唯一启用的改变是：较低起音同时被前一个高音覆盖、又和前高音结束附近的另一高音重叠，并且该恢复音是接近但不同的高音时，较低音会被记为疑似伴奏插入而跳过。规则使用当地起音间隔，不使用固定秒数门槛。同起音的“较低长音替代短高音”仍保留为待审查问题，不进入运行时，避免长停顿后的正常高音重起被误改。

每次选择写入 `main-melody.selection.json`。审计包含源索引、基线索引、最终索引、保留/跳过理由和所选轨道 ID。缺失 `confidence`、`velocity` 以及 `metadata.playback_default` 都不作为显著性或力度证据；这些值在 MuScriptor 原始输入中不能代表真实演奏力度。

源候选的起音、原始 `end_sec` 和音高保存在审计中。为了避免派生主旋律送入转谱器时因延音交叠而被拆成多声部，输出给派生渲染器的前一个选中音会把 `end_sec` 截到下一个选中起音；审计同时保存 `source_end_sec` 和 `derived_end_sec`。因此这项改动不覆盖源 raw/MIDI，但派生主旋律的显示和试听时值可能比源事件短。

主旋律尝试独立于单个分谱的成功状态。已选择的有音高轨都可以进入候选，即使某个分谱服务失败；失败记录仍保留在 `track_failures`。当全部独立分谱失败但主旋律产物成功时，任务仍为 `completed`，并通过 V2 `/score` 返回可用产物；若主旋律本身也失败，任务仍明确报告 `all_pitched_tracks_failed`。

## 验证范围

`tests/test_main_melody_hold_filter.py` 覆盖了持续高音中的低音插入、真实下行句、八度交替、恰好结束后的低音再起音、120 BPM 十六分音符、带持续跨轨伴奏的低音句、稀疏时间后的同音重复，以及派生尾音裁剪。root 复核得到全曲候选 `2041 → 1089`，选择耗时约 0.02 秒；首 45 秒为 `109 → 103`，首 20 个参考音高顺序为 `20/20`，输入深拷贝未被修改，派生事件没有交叠。正式 smoke 的最终 Score 去除 tie continuation 后有 1089 个起音，音高计数与候选一致，但仍生成 4 个声部。这些结果用于链路和局部回归检查，不证明全曲逐音顺序或完整旋律准确率。

拒绝的全局动态规划实现保留在历史提交 `5b980de`，根代理另存为 `codex/melody-dp-experiment`；`057ce18` 的运行时接线也已在本分支被恢复为上述保守策略。该实验不能作为准确率结论。

当前规则仍有不可由现有字段消除的歧义。例如 `82(0–0.9) → 70(0.5–1.1) → 79(0.9–1.3)` 可能是真实下行跳进，也可能是持续高音下面的伴奏插入；保守过滤会误删其中的 70。主旋律候选不是录音真值，也不保证全曲最准确、单声部或完整旋律。正式谱面仍可能有多个声部；本分支只改善可选的主旋律候选入口。

## 试听与诊断产物

诊断脚本会在不重跑模型的前提下导出旧基线和新候选的 45 秒 MIDI、事件 JSON，以及只表达音高顺序的 SVG/PNG 对照图。它们用于审查候选删留，不能当作已经完成节拍量化的正式简谱。生成后的文件会同时记录输入 recognition 哈希、各产物哈希和旧/新序列差异；源 raw 与原 MIDI 仍保留在原样本目录。

## 分支对比与切换

| 分支 | 用途 | 当前结论 |
| --- | --- | --- |
| `main` | 项目主线 | 保持主线行为，未接入本候选实验 |
| `v2/muscriptor` | MuScriptor V2 识别和分谱入口 | 提供 raw recognition、轨道选择和原有 V2 产物 |
| `codex/remote-audio-preview` | 远程音频预览方案 | 用于试听/预览对照，不是本算法验收分支 |
| `codex/high-accuracy-transcription`（基线 `08bf188`） | 旧高精度转谱链路 | 保留旧方案和旧产物，便于比较与回退 |
| `codex/melody-dp-experiment`（`5b980de`） | 被拒绝的全局 DP 试验 | 不推荐；会损坏开头前缀并漏掉快速旋律 |
| `codex/melody-accuracy-v1`（当前） | 保守主旋律候选和独立成功状态 | 推荐试弹，仍是候选诊断阶段，不宣称最准确 |

切换前先保存工作树，并停止正在运行的服务，避免不同分支共用旧进程或输出目录：

```text
git status --short
git stash push -u -m "before melody branch switch"   # 只有存在未提交改动时执行
# 停止当前 backend/frontend 服务
git switch codex/melody-accuracy-v1
# 按项目平时的命令重新启动服务
git status --short
git stash list
```

把 `codex/melody-accuracy-v1` 替换成上表中的目标分支即可。不要在切换流程中自动删除 stash；确认目标分支和工作树后，再由操作者手动决定是否 `git stash pop`。旧 raw、原 MIDI 和旧高精度产物不随切换覆盖。

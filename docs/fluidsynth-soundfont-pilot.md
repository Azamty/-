# FluidSynth direct SoundFont pilot

This pilot tested a direct MIDI renderer without changing the benchmark registry. The six inputs were fixed before model execution: synthetic-bass-02, special-triplet, special-complex-chord, maestro-midi-07, synthetic-piano-01, and maestro-midi-01. The first four were the previously empty-output candidates; the last two were controls.

The renderer is the official FluidSynth 2.6.0 Windows x64 C++11 asset, released on 2026-08-11: https://github.com/FluidSynth/fluidsynth/releases/tag/v2.6.0. The download URL is https://github.com/FluidSynth/fluidsynth/releases/download/v2.6.0/fluidsynth-v2.6.0-win10-x64-cpp11.zip, with 2,722,370 bytes and SHA-256 817262DEACAA748EDB3AF6731DFFE1766B00146790BECFCCC949A9F701E76681. The project-local executable and offline installation manifest are under tools/fluidsynth-2.6.0; the executable SHA-256 is 08C72384A47F67B0C5BE9EE8C88B1F0B6AFE39A8217ED2ADB83A88B41C051632. Install or verify it with scripts/install_fluidsynth.ps1 -Offline after the archive is present in .cache/packages.

The fixed command uses no MIDI input, quiet diagnostics, fast file rendering, 44,100 Hz, chorus off, reverb off, and the pinned MS Basic.sf3. The SoundFont SHA-256 is 5EA2375E8BD7D8E71DEF1036978C1621E85B66934169B6A2744B27B9B3C2D99C. FluidSynth's release tail is removed by copying exact PCM frames through the rule ceil((last source note end + 0.25 seconds) times 44,100); no resampling or source event movement occurs. The pilot checks source MIDI note-on and note-off pitch multisets through FluidSynth's event dump, then checks the output format and final frame boundary.

The six-case report is .artifacts/review/fluidsynth-soundfont-pilot-v1/pilot-report.json. All six cases passed. Each pair of renders was byte-identical, all source note-on and note-off counts and pitch multisets matched, and every output was stereo PCM16 at 44.1 kHz. The fixed outputs had durations of 9.250, 2.431837, 2.557710, 16.140635, 8.671066, and 16.250 seconds respectively. The onset diagnostic found 8, 13, 2, 87, 16, and 85 detected onsets; this is diagnostic only and does not select the renderer.

Because the renderer pilot passed, the same six WAVs were sent through the real production MuScriptor 1.2 plus one original-mix BeatNet route with benchmark seed 20260907. The model smoke is in .artifacts/review/fluidsynth-soundfont-pilot-v1/model-smoke/summary.json. Five cases returned model output and one remained a no-note failure: special-triplet. Model note counts were 7, failure, 4, 243, 23, and 127 in the fixed case order. The successful model runs used BeatNet on the original mix; evidence sources were all+bass+full_track for synthetic-bass-02, all+full_track for special-complex-chord, maestro-midi-07, and synthetic-piano-01, and all+full_track for maestro-midi-01. The selected BPM/meter were 150.0/3/4, failure, 157.8947/3/4, 65.2174/2/4, 115.3846/2/4, and 166.6667/2/4.

Relative to the previous oscillator-input production batch, this direct renderer materially changed the model result for the empty candidates: synthetic-bass-02, special-complex-chord, and maestro-midi-07 now return pitched events, while special-triplet still returns none. The controls remain model-success cases; synthetic-piano-01 returned the same 23 notes, and maestro-midi-01 returned 127 versus the earlier 123. This is evidence for a renderer pilot, not an acceptance claim: no registry replacement, 25-case regeneration, baseline/new chain, or gate change was made in this phase. The fixed FluidSynth renderer should only be adopted in a separate review after the full render-domain manifest and hashes are regenerated under this one policy.

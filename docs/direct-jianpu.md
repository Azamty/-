# 直接简谱接入

分支：`codex/direct-jianpu`。

V2 新任务默认使用「直接简谱」。识别模型与人声分离沿用项目原来的实现，新增的是识别音符到统一 Score 的整理步骤：

`识别音符 + BeatNet 拍点 → direct_notation → Score → jianpu-ly / LilyPond → SVG 与 MIDI`

旧的 MuseScore 方式仍可选择。没有记录生成方式的历史任务继续使用旧方式；伴奏重新生成时可切换，选择记录按版本保存。人声在分离完成、点击「生成人声简谱」前设置生成方式；已完成的人声任务目前需要新建任务才能更换设置。

## 页面设置

- **最短时值**：八分、十六分（默认）、三十二分音符。将起止位置吸附到拍点网格。
- **半速记谱**：音符位置和记谱 BPM 同时减半，适合拍点识别为快拍的伴奏。实际试听速度保持不变。
- **调号与转调**：例如 `1:Eb, 56:E`，表示第 1 小节为降 E、第 56 小节起为 E。小节从完整谱开头计数，包含前奏空小节；半速记谱后的小节编号也随之改变。未填则沿用分析调性；不自动猜转调。

## 整理规则

人声按单旋律处理：过滤短于 90 ms 的音、解决同网格起点冲突、截断重叠，有限度地接合很短的空隙。明显的停顿保留休止符。

伴奏按复音处理：只合并同一乐器、同一起点网格、同音高的重复记录；同键再弹时截断前音。不同音高各自保留结束位置，仅相同起止的音组成和弦。按高音、和声、低音分层，遇到持续时间重叠增加声部，空声部在相应谱行隐藏。这个分层是排版规则，不等于已经识别钢琴左右手。

多轨组合直接保留各轨声部，不再重新挑选一条主旋律替换原音符。跨小节延音、休止符与转调交给统一序列化器生成。谱面显示整体 BPM，MIDI 保留拍点的局部速度变化。

沿用项目共享拍点原点与时间线，不按第一句人声裁去前奏。不确定的弱起不擅自重排。三连音、滑音、踏板、复杂声部分配以及识别错音仍需复核。本次没有迁入针对单首歌曲写死的删音索引。

## 接口与诊断

上传 `/api/v2/jobs` 可传表单字段 `notation_engine=direct-jianpu`、`direct_options`（JSON 字符串）。轨道选择接口与人声生成接口接受同名 JSON 字段。

```json
{
  "notation_engine": "direct-jianpu",
  "direct_options": {
    "beat_divisor": 2,
    "subdivisions": 4,
    "key_changes": [{"bar": 20, "key": "E"}]
  }
}
```

API 还可配置 `vocal_min_duration_sec`、`vocal_gap_sec`、`bass_split_midi` 和 `melody_min_midi`；默认值见 `DirectNotationOptions`。参数必须是完整的一组，未提供的字段取默认值。

保留原始识别音符、原始时间 MIDI、Score JSON、整理报告、SVG、排版 MIDI 与 manifest。直接方式不产生 MusicXML；MuseScore 阶段标记为 skipped。整理报告记录删音、冲突、去重和时值调整，不能将 `unresolved_count=0` 解读为识别准确率 100%。排版后回读 MIDI，逐音校验音高和起止时值。

## 本地回归

`scripts/direct_notation_smoke.py` 可从已有音符与拍点缓存复跑完整服务，不必重新推理。运行 `--help` 查看参数；支持项目 NoteEvent 列表与 MuScriptor recognition.json。产物应保留在被 git 忽略的 `artifacts/` 下。

本次使用《染まるよ》人声和《По колу》钢琴缓存完成整曲回归。人声输入 380 音，通用规则整理为 371 音；钢琴输入 2954 音，去重后 2951 音。两者均通过排版 MIDI 回读校验；此项验证的是记谱链路，不是人工听音准确率。
